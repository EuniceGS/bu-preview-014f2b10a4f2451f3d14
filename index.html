需求明細

使用說明

以「新增客服／需求」直接登錄，再從總覽追蹤處理、驗證與回覆。WS 任務連結可視需要補入。

  1. 按「新增客服／需求」，選擇需求建立人，輸入專案或單位關鍵字後選取完整專案名稱。建立人名單為 BU 的 7 位成員；專案選單包含 22 個專案。
  2. 填寫標示 * 的必要欄位，按「儲存紀錄」。需求編號由系統在儲存成功時自動產生，不用自行填寫。
  3. 正式編號格式為 REQ-建立西元年-流水號，例如 REQ-2026-000001。所有專案共用流水號，依儲存成功順序遞增，跨年不歸零；提出日期與專案不影響編號。修改、結案或跨年度列管均保留原編號。
  4. 點需求標題或看板卡片查看內容，再按「更新辦理／回覆」修改。需求建立人保留原值，與反映人及承辦負責人分開；正式版另記錄建立登入帳號及更新歷程。
  5. 結案需填結案日期、驗證結果（通過或不適用），以及回覆與確認紀錄。暫緩或不處理需填寫備註原因；不處理另需填決定日期。
  6. 點統計卡片可篩選未結案、逾期、待驗證／待回覆或持續列管，再點一次解除。搜尋、專案、來源與狀態會一起生效；沒有需求紀錄的專案仍可選取。
  7. 「匯出目前篩選」匯出符合條件的全部需求，包含自動編號與需求建立人，不只目前頁面。

既有表單匯入

支援既有 Excel（.xlsx）、CSV 與 JSON。選工作表及欄名列後，系統依欄名規則自動對應共同欄位，可手動修正；未串接 AI。選擇專案與匯入建立人，再產生逐筆預覽。補齊日期、標題、負責人等欄位，疑似重複紀錄可略過。確認後併入示例總覽，取得新編號，保留原表編號及來源列。本機操作不長期保存；目前不提供正式批次寫入或自動合併既有需求。每次最多 500 筆。

統計口徑

未結案包含暫緩；已結案與不處理視為已結束。有預計完成日、日期早於台北今日且尚未結束才算逾期；沒有期限顯示「未排程」。需求以唯一編號計數。清單優先顯示逾期及高優先度項目。

資料保存與模式

下載的 HTML 為本機操作展示，新增及修改只在當次頁面保留，重新整理會重載示例。示例編號使用 DEMO 前綴，與正式編號分開；範例案件均為虛構。按「示例資料」或重新整理會重載資料，請先匯出需要保留的操作結果。

GitHub Pages 提供線上原型操作，資料只在當次頁面保留，並未連接共用資料庫。雲端版的示例與舊表預覽不會寫入正式資料；公司登入與分享權限仍需設定。WS API 尚未串接，填入連結不會自動派工或同步 WS。
